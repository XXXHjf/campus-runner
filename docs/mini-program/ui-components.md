# 小程序列表组件与样式复用

## 已确认的视觉基线与设计流程

用户认可当前二手首页（`pages/second-hand/index/`）和商品详情
（`pages/second-hand/detail/`）的风格。后续整改或新增页面先给设计稿，用户确认后实施；
已确认设计的明确局部微调可直接执行。设计稿用于确认布局和视觉，商品内容、状态和操作
仍以实际业务数据及权限为准，不将示例文案或图片写死在页面。

- 浅灰底、白色圆角内容区，以文字层级和留白区分信息，减少粗重分割、嵌套卡片和大面积深色块。
- 蓝色 `#0052d9` 用于主要操作和选中态；首页保留蓝色品牌栏，详情页使用连续的浅灰导航及页头。
- 按钮使用紧凑胶囊比例，字号与内边距协调，不默认拉伸填满整行；次要说明用灰色小字。
  商品详情底部按钮已人工确认的高度为 65rpx、字号 28rpx、宽度上限 180rpx。
- 优先复用 TDesign、公共组件和 `--cr-*` 令牌；相同布局统一，不为单一页面增加无意义封装。

验收先做改动范围内的轻量检查，再由用户在开发者工具或真机确认视觉及交互。
改版时保留原有状态、权限和必要操作；如需回退，只恢复本次页面布局与样式，不改变业务数据。

## 页面结构

代买订单的信息层级：我发布的列表只显示实付金额，避免把商品金额、跑腿费和实付金额压进同一行；费用拆分放在发布时的费用区和订单详情中。我发布的页面在原生标题位置使用可输入的搜索框，返回、搜索及取送位置使用项目图标；顶部搜索栏和状态分类栏固定不随列表滚动。分类按订单状态分别显示全部、待支付、待接单、进行中、已完成、已取消、退款，必须全部可见，且每个已知状态都能在对应分类找到。订单集中在有左右留白的白色内容区，订单之间只有一条分割线，订单内部用留白区分信息。接单详情先显示任务和地点，再显示需先垫付、跑腿收入及完成后预计收款，金额含义必须分开。固定操作栏应给滚动内容留出底部空间，避免遮挡联系人或凭证。

我发布的分类按 `docs/mini-program/order-flow.md` 的订单状态机核对；代买状态 `1/2` 的显示文案分别为“待购买/配送中”。验证时检查全部已知状态的分类归属、关键词与分类组合筛选、长列表滚动后导航和分类仍可见，以及窄屏七类完整显示。回退仅恢复该列表页的导航、筛选和布局，不更改订单状态或数据。

我发布的订单卡片主区域以圆角订单图片、一行 `note`（超出省略）和右侧金额排列；旧订单无图时省去图片区域，文案直接靠左。金额列固定宽度，订单状态、金额和右侧操作按钮的右边缘共用卡片内边距对齐线；金额为 0 或缺失时不显示，也不加“实付”前缀。取送地址和时间不在列表卡片展示，完整信息留在详情；搜索仍可匹配完整地址。卡片底部左侧为横向省略号操作入口，右侧按钮区按状态区分重点操作、进行中和普通操作，代买进行中按钮用暖色提示；待接单订单的更多操作可下架（取消订单并按原流程申请退款）、分享，取消用于关闭操作栏。改价和编辑当前没有可用的跑腿订单接口，不能展示无法执行的按钮。

我的接单沿用同一列表视觉：搜索栏和七个状态分类固定，分类为全部、进行中、待确认、待收款、已完成、已取消、异常。卡片首行显示发单人公开头像、订单昵称、任务类型和状态；头像缺失时用通用图标。金额为接单人应收，代买包含商品金额与跑腿报酬，无偿单不显示。操作只按接单人身份提供取件、上传送达图及收款等入口；普通单和代买单均不显示接单人主动取消入口，代买详情页亦如此。代买取件前须在详情上传购买凭证，收款失败可在详情重新处理。回退列表改造时须同步处理头像字段和详情页操作，避免入口与状态流不一致。

议价记录采用浅灰导航与统计区、白色圆角列表：左侧圆角商品封面，右侧标题、对方信息及报价，
操作与报价同排，窄屏自然换行。收到/发出仍按原有角色分开，
无留言时不渲染占位块；接受、拒绝等使用公共胶囊样式。
已接受的议价点击整条记录进入订单详情，不单独显示“查看订单”按钮；其他状态点击记录
进入商品详情。“我发出的”不显示查看商品、继续议价等独立跳转按钮，统一点击整行。
“我收到的”保留接受、拒绝操作，并阻止点击冒泡，避免一次点击触发操作和页面跳转。
订单详情将商品、进度、交付信息与金额说明合并在白色内容区，金额只在说明区展示。
线下进度为横向步骤，历史线上订单保留纵向步骤及必要的支付倒计时、金额明细。
私信和电话置于固定底部栏，电话仅在对方已提供号码时显示；无状态操作时仍可联系对方。
这些是展示调整，不改变接受议价、取消、交付、确认及收款的角色和状态约束。
人工验收需覆盖买卖双方、无电话、长地址、待交付/完成/取消状态及底部按钮换行。

二手个人列表以白色原生导航、浅灰页面背景（`#f6f8f7`）和白色内容区为基线，
蓝色用于交互，不将整片导航或页头铺成蓝色。

- 页面壳、页头、分区及空状态复用 `ui-page`、`ui-page-header`、`ui-section`、
  `ui-empty-state`。使用内容大标题时，原生导航不重复显示标题。
- `ui-page` 的 `compact` 当前只取消左右内边距，仍保留上下内边距。页头背景应
  与页面连续；不要在顶部内边距之后再铺不同底色，否则会出现横向色带。
- “我的闲置”的商品是独立管理对象，使用独立的 `ui-section plain`；用留白分组，
  不再给商品信息和操作区之间追加分割线或嵌套卡片。

## TDesign 图片与操作按钮

自定义组件宿主与实际图片、按钮不是同一层。只在宿主上写圆角、依赖按钮默认居中
行为，会出现“样式已写但图片仍直角”或“操作按钮偏离右侧对齐线”的问题。

- 商品图使用 `t-image shape="round"`，通过 `--td-image-round-radius` 设置实际
  图片圆角；列表图与外层分区统一使用 `--cr-radius-medium`。
- 收藏及闲置管理的行内胶囊按钮直接使用 TDesign `t-button`，页面导入
  `styles/second-hand-card.wxss`，通过 `t-class` 将基础类 `cr-secondhand-capsule` 和
  颜色修饰类传给按钮本体，统一使用 `size="small" shape="round"`。基础类负责常规
  字重、比商品标题小一号的字号和扁长比例（字号 26rpx、高 52rpx、左右内边距 36rpx、
  最小宽度 130rpx）；页面不再单独覆盖按钮字重、尺寸和圆角。
- 不再为基础按钮额外包一层自定义组件。统一外观由公共样式维护，状态、尺寸、禁用及
  加载直接使用 TDesign 原生属性，事件直接绑定页面方法。收藏按钮使用 `catch:tap`
  防止触发外层商品卡片跳转；独立操作区使用 `bind:tap`。
- 高亮款追加 `cr-secondhand-capsule--highlight`，搭配
  `theme="primary" variant="base"`：低饱和灰蓝实心配深色文字，用于取消收藏等高亮操作。
  描边款追加 `cr-secondhand-capsule--outline`，搭配
  `theme="default" variant="outline"`：透明底、细灰边、深色文字，用于编辑、改价、上下架等
  次要操作。按压和禁用态一并由共享样式维护，避免回退成默认高饱和蓝色。
- 每个按钮放在不伸缩的操作容器中，操作组使用 `justify-content: flex-end`，
  与商品状态共用卡片右内边距。不要用固定大边距把按钮推到右侧。

“我的收藏”已收藏项使用高亮按钮“取消收藏”，待取消项使用描边按钮“收藏”，卡片不立即
移除。取消与恢复只修改本页选择，退出该页时才提交取消；详见
[商品收藏交互](../api/second-hand.md#我的收藏离页提交取消)。

## 我的闲置快捷改价

“改价”位于“编辑”左侧，两者均用次要描边款；只对在售、已下架商品展示改价入口，
交易中、已锁定、已售出商品不开放改价。改价允许涨价或降价，不改变上下架状态，
最低价格为 0.01 元。

弹层复用 `t-popup`、`t-input`、`t-button`，只包含商品摘要、新价格和确认操作，不加入
滑尺或预设折扣。金额在提交前检查正数、最多两位小数和 99999 元上限，不限制低于原价。
保存期间防止重复提交和关闭，失败保留输入；成功后更新对应卡片价格。

保存沿用 `PUT /api/second-hand/products/{id}`，只传 `{ price }`。现有更新操作支持部分
字段，并检查商品归属及可编辑状态；不要回传整份列表对象，避免覆盖图片、描述或自提点。
金额校验与完整编辑页的价格范围保持一致，不改变接口契约。

键盘弹出时按输入框报告的原生键盘高度（px）抬升弹层，并关闭输入框自动顶页，避免双重
位移；底部安全区由 `t-popup` 保留。确认按钮复用高亮颜色类，尺寸仍采用面板常规按钮。

验证覆盖空值、零、负数、多位小数、同价、涨价、降价、重复点击、保存失败、取消、最低价，
并人工检查键盘弹出与收起。回退时一起移除入口、弹层、相关状态和新增组件注册；不涉及
数据库或后端变更。

## 验证与回退

开发只做最低必要检查，按本次改动从 JSON 注册、WXSS 导入路径、按钮修饰类与
`theme`/`variant` 配对、WXML 事件和条件、关键业务逻辑中选择相关项，不默认全量检查。
静态通过不等于实机视觉通过。

人工验收重点：图片实际圆角、单个及多个按钮的右边缘、长标题和长分类文字、窄屏
换行、在售/已下架/交易中/已售出状态，以及底部安全区。前端样式和交互由用户手动
检查并反馈；自动操作若耗费较多 token、耗时或效率低下，应停止额外操作，不持续重试
截图、点击或穷举分辨率。仅在用户明确要求时执行对应的自动验收。

回退共享样式时，应同步还原调用页的 `@import`、`t-class`、`theme`/`variant` 与对应样式，不能仅删除
共享文件；无需数据库变更，也不应回退工作区中无关的业务修改。

此前基础按钮包装导致用户反馈按钮显示异常，现已移除包装并恢复直接调用 TDesign。
统一管理不等于强制封装；不要仅为了减少重复属性恢复包装层。改价弹层的常规尺寸确认
按钮仍直接使用 TDesign，不随行内胶囊样式改尺寸。


## 跑腿大厅刷新反馈

跑腿 Tab 每次显示仍更新用户、订单和轮播数据，但保留当前列表并静默刷新。此前
`onShow → applyFilters → showLoading` 每次都会弹出“获取订单中”，同时身份检查还会
显示整页遮罩，因此正常切页也产生阻塞感。订单查询不再使用全局加载弹窗；列表为空
且正在首次加载时，使用列表内的 TDesign 加载提示。

下拉刷新必须等待本轮请求完成再停止，不提前提示成功。同条件的并发查询合并，
筛选变化、切换账号或离开页面后丢弃过期结果，避免旧结果覆盖当前列表。
请求失败保留已有列表并提示重试。

最小验证：`node --test tests/mini-program/runnerRefresh.test.cjs`。人工检查反复切换
Tab、首次加载、下拉刷新和网络失败。回退时仅同步还原跑腿首页的刷新逻辑、加载展示
及组件注册，不回退其他页面；无需数据库或服务端变更。
