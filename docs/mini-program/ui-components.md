# 小程序视觉基线与复用

## 适用范围与依据

当前统一风格以跑腿“我发布的／我的接单”、二手“我的闲置／我买到的／我卖出的”、
“我的”入口，以及跑腿和二手首页已统一的部分为参考。二手商品详情页保留已确认的
页面风格，但它的布局不直接套用个人列表。这里记录的是视觉语言和代码复用入口，
不是各页业务状态、资金含义或操作权限的定义。

二手订单详情仍未在本轮确认为统一风格的视觉样板，其当前代码中的颜色、间距和结构
只代表现状，后续设计不要以它反推新页面的基线。“议价记录”已按用户选择的第一版
设计稿改为连续白色列表，保留收到／发出分类和按角色开放的操作。“我的收藏”已按确认
的修订稿改为左对齐标题与同排搜索框、连续白色列表，不显示收藏数量；取消／恢复仍在
离页时提交。整改或新增页面先给设计稿，经用户确认后再修改页面代码；
已确认设计的明确局部微调可直接执行。

## 视觉语言

| 层级 | 约定 | 当前实现入口 |
| --- | --- | --- |
| 页面 | 浅灰底、白色内容面；主要靠留白、文字层级和轻分隔组织信息。避免粗重边框、多层嵌套卡片和大片深色背景 | `app.wxss` 的 `--cr-color-background`、`--cr-color-surface`、`--cr-color-border` |
| 首页 | 二手首页保留蓝色品牌栏和“发布闲置”入口；首页的品牌处理不延伸到个人列表的顶部导航 | `pages/second-hand/index/` |
| 个人列表 | 顶部导航为白色；需要筛选的列表固定搜索或分类栏。列表外留白、内部为连续白色圆角内容区；相邻记录用一条浅色线分隔，记录内部靠留白分层 | 跑腿两张订单列表、`styles/second-hand-order-list.wxss`、`pages/second-hand/my-products/`、`favorites/`、`bargains/` |
| 信息 | 主标题用深色和适度字重，辅助信息用较小的灰字；图片圆角；状态使用低饱和浅底标签。商品或订单金额靠右，用暖色突出 | `--cr-color-text`、`--cr-color-text-secondary`、`--cr-radius-medium`、`--cr-color-price` |
| 操作 | 蓝色用于选中态和主要操作；行内操作用紧凑胶囊，更多操作放次要位置。按钮宽度由内容决定，不默认铺满卡片 | TDesign `t-button`、`styles/second-hand-card.wxss` |

这是一套层级和节奏，不要求所有页面使用完全相同的灰色或卡片尺寸：全局背景令牌
当前为 `#f5f7fa`，“我的闲置”局部为 `#f6f8f7`，二手商品详情局部为 `#f3f4f5`。
不要把某个页面的局部值提升为全局标准。`--cr-color-price: #e7552d` 目前由上述
个人列表引用；其他页面已有不同金额色，后续按确认过的页面设计处理。

## 代码复用入口

- `app.wxss` 维护 `--cr-*` 颜色、圆角、阴影与间距令牌。个人列表已共用
  `--cr-personal-tabs-height: 84rpx`、`--cr-personal-list-gap: 24rpx`、
  `--cr-personal-item-padding: 28rpx 26rpx 30rpx`。修改这些令牌时核对跑腿两张列表、
  二手订单共享样式、“我的闲置”、“我的收藏”和“议价记录”。
- 二手“我买到的／我卖出的”使用 `styles/second-hand-order-list.wxss`；
  行内胶囊样式由 `styles/second-hand-card.wxss` 提供。已有 TDesign 控件和
  `components/ui-*` 能满足需求时直接复用，不为一页另造近似控件。
- `t-image` 的实际图片圆角需用 `shape="round"` 和 `--td-image-round-radius` 设置；
  只给外层宿主设置圆角不能保证图片本体圆角。行内按钮直接使用 TDesign `t-button`
  与现有样式类，不增加仅用于包装样式的组件。
- 商品内容、状态、金额含义和可执行操作以当前代码、接口及相应业务文档核对。
  新设计稿中的示例图片、数据和文案不得写死到页面。
- 跑腿发布方详情与接单详情共用 `styles/runner-detail.wxss` 的头像区、连续白色
  主体、地址、图片、进度和底部胶囊样式。发布方保留实付明细与自己的订单操作，
  按订单状态显示支付、退款、联系接单人和凭证，不直接复用接单方的业务处理。
- 跑腿两张订单列表及二手“我的闲置／我买到的／我卖出的”的更多操作弹层共用
  `app.wxss` 的 `cr-action-sheet`：操作黑字、取消灰字，无分隔线，按钮间距 24rpx。
  底部安全区由 TDesign `t-popup` 提供，内容区不再叠加安全区留白。

## 验证边界

只做与改动直接相关的最低必要静态检查；页面视觉和交互由用户在微信开发者工具或
真机人工验收。静态检查通过不等于界面或真机验证通过。涉及公共令牌或共享 WXSS
时，检查所有引用页；涉及图片、底部操作栏或弹层时，人工留意圆角、对齐、长文案、
窄屏和安全区。

## 反馈组件规范

本节规范已于 2026.9.27 确认并实施。业务反馈以 TDesign Toast、Message、Dialog
为基准；文中的 Modal 对应 `t-dialog`，Message 指顶部反馈条，不指聊天消息。
微信支付、授权、订阅等系统交互继续使用微信提供的能力。

### 组件选择与外观

| 项目 | Toast 轻反馈 | Message 状态反馈 | Modal 决策／重要告知 |
| --- | --- | --- | --- |
| 用途 | 当前操作的短结果、简单提醒 | 当前页面需要关注的异常、持续状态及处理入口 | 必须作出选择、确认后果，或必须明确阅读的信息 |
| 位置和样式 | 屏幕居中，TDesign 深色底；统一图标与文字横排 | 页面顶部、导航下方，TDesign 浅色语义底；不遮挡导航 | 屏幕居中，TDesign 白色 Dialog；主操作沿用品牌蓝，破坏性操作使用危险色 |
| 文案行数 | 优先 1 行，最多 2 行；建议不超过 20 个汉字 | 优先 1 行，最多 2 行；建议不超过 36 个汉字，动作另列 | 标题 1 行，建议不超过 10 个汉字；正文优先 2–4 行，常规最多 6 行 |
| 图标 | 成功 `check-circle`，失败 `close-circle`，提醒 `error-circle`；中性提示不带图标 | success／error／warning／info 使用 TDesign 对应语义图标，图标居左 | 常规不带图标，靠标题、正文及按钮表达；不叠加大号成功／警告图标 |
| 遮罩与滚动 | 无遮罩，不阻止页面滚动 | 无遮罩，不阻止页面滚动 | 有遮罩并阻止背景滚动；点击遮罩不关闭 |
| 停留时间 | 成功／中性 2 秒；失败／提醒 3 秒 | 短期状态 4 秒；需要操作或持续关注的状态不自动消失 | 不自动消失，用户通过按钮结束 |
| 操作 | 无按钮、无链接 | 最多 1 个明确动作，可带关闭按钮 | 常规 2 个按钮；重要告知可仅 1 个“知道了”；有选择的弹窗须保留退出路径 |

行数以实际渲染为准，字数只是撰写预算。不得省略、截断关键后果或用滚动跑马灯
塞入长文案。Toast 太长先精简，仍无法表达则按用途改为 Message 或 Modal；
Message 太长移到页面状态区；复杂详情、协议和多字段表单使用独立页面或已有业务弹层。
不要仅因为句子较长就增加一次强制确认。

持续 Message 使用不自动关闭的配置，业务状态恢复后主动清除。与页面状态直接相关、
离页后还可能存在的信息，重新进入时根据真实状态重建，不能只依赖一次提示。
可关闭的信息关闭后仍须有页面内的查看入口；阻止继续操作的异常不能只有反馈条，
相应操作同时禁用或给出重试入口。顶部反馈应避开自定义导航、刘海和安全区。

### 业务场景映射

| 场景 | 组件和处理 | 文案示例 |
| --- | --- | --- |
| 保存资料、添加地址、复制联系方式、提交议价成功 | 成功 Toast；收藏等已有明确按钮状态变化的操作可省略提示 | “已保存”“已复制”“议价已发送” |
| 一次操作失败，当前页可直接重试 | 失败 Toast，3 秒 | “发送失败，请重试” |
| 漏填、格式错误、未选择地址 | 优先对应输入项下的错误提示；无合适字段位置时用提醒 Toast，一次提示首个问题 | “请选择配送地址” |
| 主列表／详情首次加载失败 | 页面错误状态及重试入口；无数据时不只弹 Toast | “加载失败，请重试” |
| 已有数据的刷新失败 | Message，4 秒，保留原内容；需要时附“重试” | “刷新失败，请重试” |
| 后台刷新成功、静默更新、用户主动取消微信支付或选择图片 | 不弹成功／失败提示；主动刷新也默认不弹“刷新成功” | — |
| 网络不可用、费用无法获取，影响继续提交 | 持续 warning／error Message，提供重试；数据恢复后清除 | “费用暂时无法获取，请重试” |
| 支付已完成但订单状态尚未更新 | 持续 warning Message，附“刷新”，并显示实际订单状态 | “支付已完成，订单状态待更新” |
| 已取消订单但退款申请失败，需用户处理 | 重要告知 Modal，明确已取消与退款未成功，给出实际可用处理入口；页面保留该状态 | “订单已取消，退款申请未成功” |
| 审核中、审核未通过、收款处理中 | 优先页面持续状态；当前操作触发时可用 Message，附实际可用查看入口 | “认证材料审核中”“收款处理中” |
| 发布前缺少登录或校园认证 | 引导 Modal，说明必要条件并允许返回浏览 | “登录后继续”；按钮“暂不登录／去登录” |
| 删除地址／订单、取消订单、确认收货、接受议价、商品下架 | 确认 Modal；只说明该操作的实际后果 | “删除地址？”；按钮“保留／删除” |
| 草稿恢复、离开未保存内容 | 选择 Modal，清楚说明恢复／丢弃或保存／离开的差别 | “恢复未完成的内容？”；按钮“重新填写／恢复” |
| 提交需要等待、上传中、支付发起中 | 按钮 loading、上传进度或 TDesign Loading；不使用成功／失败 Toast 充当加载提示 | “提交中…” |

资金文案必须依据真实返回状态；不得把支付发起、退款申请提交、收款处理中写成
“支付成功”“退款到账”“收款到账”。本次统一不调整支付、订单、认证业务规则。
已存在的核对订单、取消原因、议价输入等业务弹层保留自身用途，不强行改成普通 Dialog。

### 文案和提示节奏

- 只表达结果、原因或下一步；不显示接口、字段、token、英文错误码、原始异常和堆栈。
  动态错误先转换为适合用户阅读的文案，不直接透传 `error.message`。
- 确认弹窗采用具体动作标题及按钮，如“取消订单？”、“继续保留／取消订单”；
  避免所有业务都写“提示／确定／取消”。后果无法由代码确认时先核对业务规则。
- 同一次操作只保留一处结果反馈，网络层和页面层不重复弹出。同一页面不叠加多个 Toast；
  高频重复提示合并，离页后不再在旧页显示异步反馈。
- Message 默认单条展示；持续的关键状态优先于短期消息，短期消息不能把它覆盖。
- Modal 显示时不再叠加背景 Toast／Message。确认提交时防止重复点击；失败时保留
  可重试的上下文，在弹窗内显示简短错误，避免叠第二个 Modal。
- 页面跳转不能立即吞掉结果提示；以目标页的实际状态或一次反馈承接，不为读完 Toast
  强制用户等待。提示宿主与异步请求要跟随当前页面／组件生命周期。

### 实现入口与维护约束

统一前的 2026.9.27 静态盘点（排除依赖目录）：存在 104 处 `wx.showToast`、21 处
`wx.showModal`、11 处直接 `Toast(...)` 调用，以及多处旧 Toast 工具调用；
未发现 `Message.info/success/warning/error(...)` 调用。这是源码调用点数量，
不代表运行次数。`commonJs.js` 同时存在横排和竖排封装；其“有遮罩”注释与实际
配置不符，`preventScrollThrough` 不等于 `showOverlay`。

当前业务源码已移除直接的 `wx.showToast`、`wx.showModal` 和页面内独立 Dialog。
`utils/feedback.js` 统一调用策略，`components/ui-feedback/` 承载 TDesign 的 Toast、
Message、Dialog；每个页面仅挂载一个 `ui-feedback`，需要独立反馈的自定义组件也在
自身作用域挂载宿主。页面宿主通过 `app.json` 注册，导航为自定义时传入
`custom-navigation="{{true}}"`，使 Message 避开顶部导航。

- `showToast(context, { title, theme })`：短结果；语义为 success／error／warning／info。
  时间、横排、遮罩由共享入口统一配置。当前短文案预算为 24 字，超过时使用短期
  Message；动态短提示超过 36 字或包含实现术语时使用完整、简短的兜底文案，不截断显示。
- `showMessage(context, content, { theme, persistent, key, action, onAction })`：顶部状态反馈。
  持续反馈不自动消失、不提供关闭按钮；使用 `clearMessage(context, key)` 在状态恢复时
  清除，避免误清另一种状态。当前实现等待 TDesign 的关闭动画结束后再复用单条消息。
- `showModal(context, options)`：返回确认结果，同时兼容原调用的 success／fail／complete。
  `confirmText`、`cancelText` 使用具体动作；破坏性操作传 `danger: true`。
  业务取消和因离页、重复弹窗而中止严格区分：中止不执行 success 中的取消分支，避免
  误清草稿。确认后的异步操作未结束时阻止重复确认，失败反馈保留在原确认上下文中
  供用户重试。登录／认证前置引导和退款重要告知可显式使用 `allowDuringAction`；
  普通业务调用不应开启它。不要把缺失宿主当成用户拒绝。
- `loadError`、`loaded` 配合页面错误状态、固定的 `retryFeedbackLoad` 事件和重试入口；
  已有内容的刷新失败保留内容。恢复数据前不把错误显示为“暂无内容”。
- `navigate` 在目标页宿主就绪后承接一次结果反馈；共享宿主会清理隐藏页的短提示与
  未完成弹窗，并恢复同一页面仍有效的持续状态。离页提交收藏失败是明确例外：在当前页
  给出反馈及返回收藏的入口，而非向已销毁页面显示提示。
- `commonJs.js` 的旧 Toast 名称保留为兼容入口，全部委托共享策略；`transformers.js`
  的 `showError`／`showSuccess` 现在必须传入页面 context 和文案。不得直接导入 TDesign
  反馈 API 绕过统一策略，不得全局覆写微信方法，不得以原生提示兜底掩盖宿主缺失，
  不修改第三方构建产物。

微信支付、收款、授权、订阅及原生加载等待能力维持原调用；Toast、Modal、Message
统一不改变它们的业务判断。

如需回退此轮统一，必须同时回退共享反馈工具、宿主及受影响调用和注册，避免只回退
某一侧造成无提示或找不到组件；保留与此轮无关的页面改动。

检查仅覆盖改动语法、组件注册与宿主、共享工具调用方、确认／取消分支、提示清理及
与导航相关的行为。视觉、长文案换行、遮罩、导航安全区和真机交互由用户人工验收。
