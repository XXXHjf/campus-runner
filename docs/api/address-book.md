# 地址簿接口

## 公开校园筛选

`GET /api/address/three` 是校园、校区、建筑类型和楼栋的公共字典，不包含用户地址簿、
手机号或详细地址。游客和未选择学校的账号返回所有有效学校的字典；有学校的账号仍按学校筛选。
各 `getThree` 查询以空 `schoolId` 表示全部学校，不能用于个人地址查询。
个人地址的 `/api/address`、`/show` 及所有写入仍要求登录。
验证游客筛选、有学校筛选、个人地址匿名请求返回 401；回滚时同步回滚游客筛选客户端，无迁移。

## 地址详情修改

`PUT /api/address/update` 用于修改当前用户自己的地址。`id` 必填；校区、楼栋、详细地址和
标签只更新请求中明确提供的字段。

`details` 和 `label` 的更新语义如下：

- 不传或传 `null`：保留原值。
- 传非空字符串：替换原值。
- 传空字符串：清空原值。

必须区分“未提供”和“主动清空”，否则用户在地址详情页删除已有标签或详细地址后，接口会
表面成功但数据库仍保留旧内容。小程序清空 TDesign 输入框时也必须监听 `clear` 事件，将
页面状态同步为空字符串。

## 验证

1. 打开一个已有标签和详细地址的地址。
2. 分别点击输入框的清空按钮并保存。
3. 重新进入地址详情，确认被清空的字段仍为空；修改为其他文字后再次保存也应成功。
4. 只修改默认地址或楼栋时，未提供的可选文本字段应保持不变。

## 回滚

本调整不改变数据库结构，回滚 API 和小程序代码即可，不需要执行数据库迁移。已经由用户
主动清空的标签或详细地址不会自动恢复，若需恢复只能由用户重新填写或从业务备份找回。

## 默认地址规则

只要用户有未删除地址，就保留一个默认地址。第一条地址自动设为默认；已有默认地址不能直接取消，只能将另一条设为默认来替换。删除默认地址后，按自增 ID 降序选择最近添加的未删除地址；删除最后一条后允许没有地址。

`PUT /api/address/update` 接受可选 `isDefault`（0 或 1）。不传保留状态；1 将本地址设为默认；当前默认地址传 0 返回“请将其他地址设为默认地址”，整次修改不保存。默认状态与详细内容在同一事务内提交。旧 `PUT /api/address` 仍用于设默认，并复用同一保存逻辑。

新增、编辑、设默认、删除均先锁定当前用户行，避免并发首次新增或替换产生重复默认；写入时修复该用户历史无默认或多默认数据，已有唯一默认则保留。无需数据库结构迁移，历史数据不会仅因打开页面就被改写。

最低验证覆盖首次新增、默认替换与内容同步保存、拒绝取消默认、删除后的最新地址补选、删除最后一条、写入失败回滚以及保存后重新读取。界面仍需在微信开发者工具或真机人工验收。回滚 API 与小程序需配套进行；已变更的默认状态不会自动恢复。
