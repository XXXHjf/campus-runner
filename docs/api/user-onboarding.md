# 用户登录、资料注册与校园认证

## 核心约束

微信登录和资料注册是两个不同阶段。`POST /api/user/login` 会在首次登录时创建仅含
OpenID 的用户记录，以便签发 token；这条记录存在不代表资料注册完成，客户端不得再使用
`create_time == update_time` 或“数据库中已有用户”判断注册状态。

头像、有效昵称和有效手机号共同构成注册资料。`GET /api/user` 返回
`profileCompleted`：三项全部有效时为 `true`，否则为 `false`。昵称 `微信用户` 视为占位值，
手机号必须是有效的中国大陆 11 位手机号，头像必须已经绑定为用户头像资源。

`PUT /api/user` 提交校园认证前会再次校验注册资料。资料不完整时返回简洁的用户提示，
因此旧客户端、历史半成品账号或异常页面跳转也不能绕过此顺序。

## 进入小程序后的状态流转

| 当前状态 | 浏览及进入“我的”时的处理 | 主动进行身份操作时 |
| --- | --- | --- |
| 本地无 token | 游客浏览，不调用微信登录、不创建账号 | 弹出可取消的登录确认 |
| 已有账号但头像、昵称或手机号缺失 | 可继续浏览，不自动跳转 | 需要认证的操作提示完善资料及认证，可取消 |
| 注册资料完整，校园认证未提交或被驳回 | 可继续浏览，不自动跳转 | 提示去认证或查看驳回原因，可取消 |
| 校园认证审核中 | 保留正常登录态，可继续浏览 | 提示等待审核，提供查看进度与继续浏览 |
| 校园认证已通过 | 进入正常使用状态 | 可使用要求认证的业务能力 |

历史账号主动进入校园认证流程时，仍需先补齐缺失的注册资料；浏览不受影响，
不会清空或重复提交认证材料。登录成功本身不强制进入注册或认证。

## 客户端跳转规则

- 注册资料是否完整统一由 `utils/profileStatus.js` 判断；页面不得各自复制条件。
- 资料页保存后必须重新请求 `GET /api/user`，确认 `profileCompleted=true`，再进入校园认证。
- 校园认证页加载时必须检查资料完整度，不完整则返回资料注册页。
- 启动只恢复有效缓存，401 清理过期身份，不自动微信登录、不重放写请求。
- `accessGuard` 只从身份操作入口调用；取消登录不发登录请求，不跳转、不执行原操作。
- “我的”生命周期不得因资料不完整再次跳转，避免资料页返回后被立即拦回。
- 资料页有“返回浏览”；认证须知取消和资料页返回在无上级页面时回二手首页。
- `chooseAvatar` 返回的是本地临时文件；开发者工具或不同基础库可能返回 `http://`、
  `wxfile://` 等形式。注册页必须根据“用户本次是否选择了头像”决定上传，不得用 URL
  协议判断它是否已经是服务端图片。只有上传取得媒体资源 id 并完成绑定，头像才算保存成功。

## 验证方法

轻量检查：`node --test tests/mini-program/guestAccess.test.cjs tests/mini-program/runnerRefresh.test.cjs`。
无登录态应可读取二手分类、列表、详情和跑腿公开预览；写入、个人订单、私信、地址簿仍需登录。
公开权限同时限定 HTTP 方法与路径，不能用 `/products/**` 放行我的商品、私信或写入。
用户拦截器开始与完成请求时清理线程身份，避免线程复用让游客继承前一个用户。

至少覆盖以下账号状态进行真机回归：全新账号、仅生成用户记录、只保存部分资料、资料完整但
未认证、审核中、审核被驳回、已认证但历史资料缺失、资料完整且已认证。重点确认中断注册后
重新进入会回填已保存内容，且任何状态都不能在资料不完整时提交校园认证。

头像回归还应覆盖开发者工具返回 `http://` 临时路径的场景，确认注册保存请求携带
`headImgAssetId`，随后 `GET /api/user` 返回 `profileCompleted=true`。

API 自动化测试应覆盖 `profileCompleted` 的真假判定、非法手机号更新被拒绝、资料不完整时
校园认证提交被拒绝。

## 回滚

游客浏览修改不涉及数据库迁移。上线需先部署提供公开读取的 API，再上传小程序；
若仅回滚 API，已发布的游客小程序会无法读取列表，应成对回滚客户端与 API 或保留公开读取兼容。
恢复旧版前须检查是否重新引入强制注册和取消返回循环。

回滚小程序时，应同时回滚依赖 `profileCompleted` 的跳转逻辑；API 的校园认证前置校验可以
单独保留，它只会拦截不完整资料，不涉及数据库结构变化。若必须整体回滚，应先确认线上旧版
客户端不会再次允许半成品账号绕过资料注册。
