# 统一图片资源接口

项目内新增图片统一采用“临时上传、业务提交时绑定”的两阶段流程。客户端不再把上传接口返回的
签名 URL 保存到业务表。

## 标准流程

1. 客户端上传图片，获得 `mediaId` 和仅用于预览的 `previewUrl`。
2. 用户确认业务表单时，把 `mediaId` 随业务 DTO 一起提交。
3. API 在同一事务中写入业务记录并把临时资源绑定到该业务主键。
4. 用户替换或取消选择时，客户端主动释放未绑定资源；其他遗留临时资源在 24 小时后自动清理。
5. 查询业务数据时，API 根据业务权限生成新的签名 URL。

`previewUrl`、业务查询返回的图片 URL 都可能过期，不得持久化或作为资源身份使用。

### 草稿图片检查与预览刷新

`GET /api/media/images/temporary?ids=1,2&purpose=ORDER_IMAGE` 使用登录账号检查最多 9 个
正数图片 ID。仅返回本人、指定用途、状态 TEMP 且尚未过期的资源及新的 1 小时预览 URL；
缺失、过期、其他账号、用途不符或已绑定资源统一不返回，不暴露其状态或文件地址。
检查不续期、不绑定、不释放资源，仍沿用 24 小时临时资源清理规则。状态检查不能代替
提交事务中的绑定校验，也不证明外部存储被人为删除的文件仍存在。

跑腿恢复草稿时和提交前调用该入口。恢复时移除失效或未完成上传的缓存图片并提示重传，
保留其他图片、文字和表单内容；有效图片更新预览。查询失败保留所有内容，并暂停本次提交。
换号或离页后的迟到检查结果不回写。草稿保存 7 天不代表图片保留 7 天。

验证使用 `MediaAssetServiceImplTest` 和 `draftImageAvailability.test.cjs`，覆盖账号、用途、
状态、过期、请求上限、预览更新、网络失败及旧缓存。无需迁移；部署顺序为 API 在前，
小程序在后。回退 API 前须同步回退调用新入口的小程序；缺少入口时客户端将保留内容并
阻止带图提交，不能伪造检查成功。界面恢复和重传由用户人工验收。

### 二手发布中的图片释放边界

二手发布及编辑在发送提交请求前保存本次图片 ID 快照。提交中禁止删除图片或重复提交；
离开页面不释放正在提交的图片，迟到响应也不再操作已离开的页面。成功后保留已提交图片；
收到明确的业务失败响应（HTTP 200、`code=0`）后，才允许释放本次未使用图片。
网络中断、非 200 或缺少成功码的响应不能证明提交失败，相关图片不由离页动作主动释放，
由既有服务端流程处理未绑定资源。更早的一次提交结果不明时，后续失败也不能解除那次保护。

已保存二手草稿引用的图片在普通离页时保留，失败提交后仍可由草稿恢复；明确放弃
草稿或移除图片时只释放未受提交保护的临时图片。

该边界仅解决误释放，不保证重复发布幂等，也不延长临时图片有效期。验证使用
`secondHandPublishUpload.test.cjs` 覆盖提交中退出、成功、明确失败、结果不明和再次失败。
无需数据库迁移；客户端回退会恢复离页释放竞态，应保留该保护逻辑。

## 上传和释放

用户端：

```http
POST /api/media/images
DELETE /api/media/images/{mediaId}
```

管理端：

```http
POST /admin/api/media/images
DELETE /admin/api/media/images/{mediaId}
```

上传 URL 使用 `?purpose=ORDER_IMAGE`（按用途替换），请求体使用 `multipart/form-data`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `file` | file | 图片文件 |
| `purpose` | string | URL 查询参数，图片用途，见下表；不要重复放入 multipart |

成功结果：

```json
{
  "mediaId": 123,
  "previewUrl": "临时签名地址",
  "status": "TEMP",
  "expiresAt": "2026-07-30T12:00:00"
}
```

## 统一图片处理与压缩

所有新图片都通过上述上传入口处理。客户端可以在上传前做一次温和压缩以减少弱网耗时，
但客户端结果不作为可信输入；API 必须完成格式识别、完整解码、像素上限校验、EXIF 方向
纠正、去除元数据、按用途缩放和重新编码，再将处理后的文件写入 OSS。这样旧客户端、管理端
和绕过客户端校验的请求都会得到一致结果。

上传原文件最大为 10MB，单边不超过 12000 像素，总像素不超过 4000 万；支持 JPEG、PNG
和静态 WebP，动态图片会被拒绝。处理后的规则如下：

| `purpose` | 输出格式 | 最大尺寸 | 建议质量 | 最大输出 |
| --- | --- | --- | --- | --- |
| `ORDER_CATEGORY_ICON` | PNG | 512 × 512 | 无损 | 512KB |
| `SECOND_HAND_CATEGORY_ICON` | PNG | 512 × 512 | 无损 | 512KB |
| `SECOND_HAND_PRODUCT_IMAGE` | JPEG | 1600 × 1600 | 84% | 1MB |
| `ORDER_IMAGE` | JPEG | 1920 × 1920 | 85% | 1200KB |
| `DELIVERY_PROOF` | JPEG | 1920 × 1920 | 88% | 1400KB |
| `PURCHASE_PROOF` | JPEG | 1920 × 1920 | 88% | 1400KB |
| `AVATAR` | JPEG | 512 × 512 | 85% | 400KB |
| `STUDENT_CARD` | JPEG | 2400 × 2400 | 90% | 1800KB |
| `BANNER` | JPEG | 1404 × 440 | 88% | 800KB |

当首次编码超过用途上限时，API 会先逐步降低 JPEG 质量，再逐步缩小尺寸；PNG 仅缩小
尺寸，不转为有损格式。学生证照片优先保留文字清晰度，轮播图仍由
管理端完成比例裁切，但最终格式和容量由 API 统一兜底。

验证时至少覆盖大尺寸 JPEG、透明 PNG、WebP、伪造文件头、超像素图片以及不同用途的
输出尺寸和容量。回滚本处理规则不涉及数据库：可回滚 API JAR 和客户端版本，同时恢复
对应的 multipart 配置与生产启动脚本；已生成的标准图片仍可被旧版本正常读取。

## 上传失败处理与验证

上传入口前的 Nginx 请求上限必须与 Spring 的单请求 `20MB` 上限保持一致，具体配置、
验证及回滚见 [Nginx 图片上传大小限制](../deployment/nginx-deployment.md#图片上传大小限制)。
小程序公共上传服务先处理 HTTP 状态：413 提示压缩后重试、401 提示重新登录，其他
HTTP 错误及非 JSON 成功响应使用通用中文提示，不向用户展示 HTML 或内部错误。
HTTP 200 的业务失败保留 API 返回的可操作提示，正常上传和压缩规则不变。

在仓库根目录运行 `node --test tests/mini-program/mediaService.test.cjs`，覆盖上述响应
处理、上传前压缩和仍然超限时的本地拦截。该测试使用模拟的微信 API，不替代开发者工具
及真机上传验证；测试文件放在小程序目录之外，避免打入发布包。

## 用途与业务字段

| `purpose` | 业务提交字段 | 数量 | 可见性 |
| --- | --- | --- | --- |
| `ORDER_CATEGORY_ICON` | `imageAssetId` | 1 | 公开 |
| `SECOND_HAND_CATEGORY_ICON` | `imageAssetId` | 1 | 公开 |
| `SECOND_HAND_PRODUCT_IMAGE` | `imageAssetIds` | 最多 6 | 公开 |
| `ORDER_IMAGE` | `imageAssetIds`（旧版单图入参 `imageAssetId` 仍可用） | 1～9 | 私有 |
| `DELIVERY_PROOF` | `imageAssetId` | 1 | 私有 |
| `PURCHASE_PROOF` | `imageAssetId`（代买确认购买） | 1 | 私有 |
| `AVATAR` | `headImgAssetId` | 1 | 公开 |
| `STUDENT_CARD` | `studentIdCardAssetId` | 1 | 私有 |
| `BANNER` | `imageAssetId` | 1 | 公开 |

公开图片查询 URL 的签名有效期为 7 天。学生证、清晰订单图片、购买凭证和送达凭证只能通过已完成
业务鉴权的接口返回，签名有效期为 15 分钟。待接单订单另提供受限的模糊浏览图片，规则见下文。

签名到期时间按时间窗口取整：公开图片为 1 小时，私有图片为 5 分钟。同一对象在窗口内
取得相同 URL，便于小程序切换页面时复用图片缓存；实际有效期最多分别缩短 1 小时和
5 分钟。签名过期后重新请求业务列表或详情即可取得新地址，不得把签名 URL 存为图片身份。
跑腿订单列表使用 320px、二手商品首页列表使用 480px 的正方形签名缩略图，
按封面显示区域居中裁剪、JPEG 品质 75%、不放大源图；商品详情及有完整权限的订单详情使用原图，
跑腿浏览图片使用保留比例的 320px 模糊版本。
分类图标限制在 96 × 96px 内，保留透明背景；头像限制在 256 × 256px 内，JPEG 品质 80%。
缩略图由 OSS 按请求生成，不改变已存储对象或数据库结构。

公开用途的图片签名包含 `response-cache-control=private,max-age=3600`，允许设备缓存
1 小时；`private` 阻止共享代理缓存，不能据此把存储桶改为公开访问。私有图片的签名有效期
和响应缓存规则沿用现有行为。首屏跑腿前三张、二手前四张图片立即加载，其余使用 TDesign
的 `lazy` 属性，避免屏幕外图片同时争用首屏下载资源。
小程序默认头像使用包内 `images/default-avatar.png`，与原占位图一致，首次显示无需访问
外部图片域名；注册页仍须上传用户选择的头像，不把默认头像计为已完成头像设置。

验证需检查图片响应的缓存头、首屏加载和滚动后的图片显示；历史抽样体积不能作为当前手机端性能结论。缩略图规则回滚不改变原始对象或数据库结构。

跑腿发单和待接单内容编辑按 `imageAssetIds` 的顺序保存图片。订单详情返回
`imageAssetIds`、`images` 数组；原有 `imageAssetId`、`image` 继续返回第一张，
供订单列表封面及旧版调用方使用。被编辑移除的图片按原有媒体清理延时处理。

## 管理端学生认证图片回显

`GET /admin/api/auth/pendingList`（审核管理）与用户管理的待审核列表、用户详情均需在
管理员鉴权后解析媒体绑定。用户表查询本身不再包含头像和学生证图片，不能直接把查询结果
返回给审核页面，否则已有材料会显示为“无”。头像使用公开绑定解析，学生证使用
`resolveAuthorizedBinding(USER_STUDENT_CARD, userId, STUDENT_CARD)`，返回
`studentIdCardAssetId` 和短期签名地址 `studentIdCard`；不得改为公开资源或恢复旧图片列。

用户详情抽屉在“认证信息”中展示 `studentIdCard`，支持查看大图；全部用户、已认证及待审核
列表共用该详情入口。图片展示不以审核状态为条件，已审核材料仍可查看。加载失败时重新获取
详情以更新签名地址，无绑定时显示空状态。学生证审核状态须按 `0` 未审核、`1` 审核中、
`2` 已通过、`3` 未通过显示，不能复用仅判断 `1` 的认证状态逻辑。

验证：运行 `mvn -Dtest=AdminAuthServiceImplTest test`，覆盖有材料、无材料及空列表；
上线后使用管理员账号刷新审核列表并打开“查看材料”，确认学生证可预览，签名过期后刷新列表
可重新获取地址。该修复不涉及数据库迁移，回滚仅恢复发布前 API JAR，但会重新出现图片缺失。

## 生命周期

- `TEMP` 资源只能由上传者绑定，且用途必须匹配。
- 已绑定资源不能通过临时资源删除接口删除。
- 替换或删除业务图片后，旧 OSS 对象进入 7 天延迟删除期。
- `tb_media_asset.bound_type + bound_id + sort_order` 是新图片与业务记录的标准关联。
- 业务表不再存图片 URL 或媒体资源 id；`tb_media_asset` 绑定是唯一图片身份来源。
- 已弃用的 `/api/upload` 已删除，所有客户端必须使用本页的按用途上传接口。
- 历史图片运行时迁移器和旧字段回显兜底已经删除。

数据库首次接入执行 `docs/database/media-asset-migration.sql`；已执行第一阶段迁移的环境，在发布
本版本 API 前执行 `docs/database/media-asset-phase2-migration.sql`。
已完成历史迁移的环境执行 `docs/database/legacy-compatibility-cleanup.sql` 删除旧字段；停机发布、
验证和回滚要求见 `docs/database/legacy-compatibility-cleanup.md`。历史迁移文档与 SQL 仅保留作审计记录。

### 私有绑定解析的授权责任

`resolveAuthorizedBinding` 是受信任的服务内解析方法，只根据绑定查询并签名，不自动识别当前用户是否有业务权限；不得直接暴露为按绑定 ID 查询图片的用户端接口。调用方必须先核对业务归属及状态，再解析私有图片。跑腿详情、联系人、购买凭证、送达图片及接单列表规则见 [订单资料与凭证读取权限](../mini-program/order-flow.md#订单资料与凭证读取权限)。公开预览不能调用私有解析，也不能把旧 URL 当作权限校验后的兜底返回。


## 列表中的公开媒体批量读取

二手商品列表（含个人、收藏及管理端列表）按业务编号批量读取公开商品图片；二手订单列表批量读取商品图片及交易对方公开头像，支付超时配置按列表读取一次。图片保留 `sort_order, id` 顺序、原预览尺寸与签名期限，缺失图片不回退历史原始 URL。

内部 `resolvePublicBindings` 对编号去重、按 200 个一批查询，只返回匹配业务类型、用途、`BOUND` 状态及 `PUBLIC` 可见性的资源，服务层再次过滤。它不提供客户端批量入口，不替代跑腿参与者或其他私有图片的授权链路。商品首页、个人发布、收藏及二手买卖订单已在 SQL 中按页读取后批量解析公开图片；其余列表分页、返回上限及限流仍属未完成整改，不能把减少查询次数视作已限制所有列表的读取量。

验证包括 MyBatis 生成 SQL 的过滤条件、批次上限、重复编号、私有及错误用途资源不签名、列表调用次数和现有媒体/二手业务测试。未执行真实数据库性能测试或生产发布。


账号、IP 及上传累计额度目前尚未实施；现有大小、用途和张数检查不能代替速率、并发和累计存储额度。已核对事实、初始方案、上传预占及回滚边界统一见[请求频次与上传额度保护方案](../deployment/server-operations.md#请求频次与上传额度保护方案尚未实施)。


跑腿“我发布的”列表使用内部 `resolveAuthorizedBindings`，业务服务在任何签名前校验整页订单均属于当前发单人，再按去重订单编号批量读取。仍校验业务类型、用途、BOUND 状态及 PUBLIC/PRIVATE 可见性；私有签名保留 15 分钟期限、320px 预览，分类图标另以公开批量读取。不提供客户端私有批量入口，也不授权其他跑腿列表复用这一身份判断。


跑腿“我接的”分页从同次 SQL 读取接单归属和状态，在整页归属校验后，仅为有效接单（0/1/2）的订单图片、送达凭证及采购凭证批量签名，私有 15 分钟期限保留，列表使用 320px 预览；分类图标和发单头像分别公开批量解析。取消接单历史清除旧图片和私有内容，其私有字段也不进入服务端关键词匹配。内部归属字段使用 `JsonIgnore`，无客户端授权或私有批量入口。


个人议价记录封面在 SQL 分页后按商品编号批量读取公开图片，复用类型/用途/BOUND/PUBLIC 校验及原排序，使用 480px 列表预览，缺失封面保持为空。商品议价权限先在业务层判定卖家或当前买家，再由 SQL 在分页前限定身份；批量公开封面不替代议价记录的身份校验。


跑腿大厅 `/api/order/feed`、游客浏览 `/api/order/public` 及非参与人的待接单详情正常返回发单昵称、头像、任务说明、门禁、报酬、预计送达时间与楼栋地址；说明保持原文，不过滤其中的联系方式。大厅统一使用公开地址快照，不返回电话、详细位置、订单号及图片资源 ID。说明与公开地址在 SQL 分页前参与搜索，头像及分类图标按当前页批量解析。校园认证、学校筛选及实际接单条件保持原规则。

任务图片使用内部 `resolveOrderPreviewBindings`，仅接受订单编号，查询同时限定订单未删除、待接单、存在取送地址快照，以及媒体为 ORDER / ORDER_IMAGE / BOUND。固定签发 `image/resize,m_lfit,w_320,h_320,limit_1/blur,r_30,s_20/quality,q_75` 模糊图片处理地址，期限 15 分钟；模糊参数属于签名内容，不能将处理地址删掉参数后当成原图地址。接单详情在原图片尺寸外层裁切、叠加白色半透明蒙层，并禁止接单前打开清晰预览。主页卡片保持原图文布局，不新增头像昵称行或图片蒙层结构。采用 OSS 全图模糊参数，参见[官方图片模糊说明](https://help.aliyun.com/zh/oss/user-guide/blur)。不修改图片私有存储属性，不回退旧 URL，也不放开通用私有媒体批量入口。

详情中的电话、完整地址与清晰任务图片仍只授权发单人或有效接单人，非参与人的已接单及结束订单不开放详情。浏览昵称取发单账号的 `tb_user.username`，参与人详情的头像区使用 `senderNickname`，不覆盖订单中的联系人名称。`viewerIsTaker` 由当前登录账号及有效接单记录计算，接单详情优先以此决定清晰图片及接单操作，不依赖“我的接单”分页列表；兼容旧服务响应时保留原身份判断路径。详情门禁 0/1 对应无／有门禁，2、缺失或无效值显示“暂不清楚”；主页只在明确为 1 时显示原“门禁”标签，不增加无门禁或未知标签，代买保持原门禁区域显示规则。

验证：定向权限、查询与签名测试和小程序刷新逻辑检查；微信端蒙层、图片裁切与模糊强度由用户人工验收。未执行真实 OSS 图片请求、真实 MySQL 或生产验证。回退时需同时回退公开字段投影、模糊解析及页面展示；数据库结构无变化，原清晰图片授权不能放开。


管理端二手商品列表也在 SQL 分页后批量解析当前页公开商品图片，保留原尺寸、类型/用途/BOUND/PUBLIC 校验和缺失资源清空规则。顶部在售数量改为同筛选范围的完整计数，不读取额外商品明细或图片；详情仍单独按商品编号读取。其余管理端列表尚未完成分页核对。


管理端二手订单列表已在 SQL 分页后批量读取当前页商品公开图片，保留原尺寸和缺失清空规则；历史线上待付款的支付期限配置每页最多读取一次。完整筛选范围的异常数和金额汇总不读取额外图片或订单明细，详情单独按编号读取。管理端议价和留言也已分页，其管理列表原本不解析媒体，待回复数量由完整汇总取得；其他入口仍待继续核对。


用户二手会话列表在数据库按最近消息分页后，先核对整页当前账号及商品归属证明，再批量解析当前页未删除商品的公开图片，保留原图片尺寸及类型/用途/BOUND/PUBLIC 校验。已删除商品不解析媒体，内部证明不序列化；不逐会话读取商品详情，不回退历史 URL。消息历史已使用游标分批查询，轮询不再重复解析商品媒体；未执行真实 MySQL 或生产验证。
