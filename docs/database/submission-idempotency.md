# 创建请求幂等

适用于跑腿订单创建、二手商品发布、二手订单创建。商品编辑等操作不在本次范围内。

## 当前约束

三类创建 DTO 必须携带 `clientRequestId`（16–64 位字母、数字、下划线或连字符）。服务端按账号、操作类型和标识唯一保存首次创建结果；相同标识的不同内容返回 HTTP 409，不再创建。JSON 对象键顺序及标识字段本身不参与内容摘要，数组顺序参与。

`SubmissionService.execute` 将占位、业务创建和结果保存放在同一 Spring 事务中。InnoDB 唯一主键及行锁让多个进程使用同一标识时串行处理。事务失败回滚后可用原标识重新创建；已经提交的结果直接重放，不重复绑定图片、生成订单或修改商品状态。出现异常的残留占位或无法解析的结果时返回 HTTP 409，需排查，不能直接再创建。

跑腿订单插入 Mapper 不另起事务拦截边界，创建服务仍管理事务。这避免订单编号冲突被内层事务标记为只能回滚，导致捕获异常后的编号重试无法提交。

认证仍在重放前检查。结果记录含订单或商品信息，按私有业务数据管理，不输出到日志。记录当前不设自动清理期限，不能在客户端仍可能重试时删除，否则旧标识可能再次创建业务。

小程序在发送前按账号持久化标识和完整原内容；存储失败不发送。未确认结果保留原内容，重启后重试原提交。明确成功且有有效 ID，或 HTTP 200 明确业务拒绝，才清除。HTTP 409、服务器未知异常（HTTP 500）、网络失败和损坏响应均保留。重复点击共享进行中的请求；页面恢复使用现有确认弹窗及反馈组件。跑腿原截止时间、金额和图片不在重试时重算或重新绑定校验。

未确认提交记录与普通草稿分开保存，退出登录不表示已取消服务端业务，因此保留记录供原账号重新登录后确认；其他账号无法读取。普通草稿仍按原退出登录规则清理。待确认期间不能用新的内容替换同一提交。

## 发布及验证

1. 按 `../deployment/server-operations.md` 完成生产必检并备份数据库。
2. 执行 `submission-idempotency.sql`。脚本有意不使用 `IF NOT EXISTS`：已存在表需先核对结构，不得忽略结构差异。核对 InnoDB、三个主键列、大小写敏感 ASCII 标识、结果列允许 NULL。
3. 建表后再启动依赖此表的 API。新 API 要求标识，旧小程序将被拒绝创建；必须协调小程序上传和用户更新、维护窗口，不能单独发布 API 后假定旧版本兼容。
4. 在隔离数据库验证同标识并发请求只产生一条业务；模拟响应丢失后重试返回原 ID；同标识不同内容返回 409；创建失败后占位与业务同时回滚；不同账号相同标识相互隔离。验证所有三类创建及原图片关联、商品状态。
5. 小程序人工验证重启后的确认入口、图片过期或已绑定、商品已进入交易中时的订单恢复，以及账号切换后的隐藏和恢复。

本地 Mockito 和 VM 逻辑测试不代替真实 MySQL 并发和小程序人工验收。2026-10-12 已完成生产建表与 API 发布，并在隔离恢复库演练迁移；小程序由用户立即配套发布，真实账号并发及真机验收仍待完成。证据和回滚位置见 [业务发布记录](../deployment/server-operations.md#2026-10-12-业务发布记录)。

## 回滚

回滚 API 和小程序应协调进行。保留幂等表和已有记录；回滚到无幂等支持的 API 后，旧待确认请求不得自动发送为新创建，应通过原业务记录核对结果。禁止把删除幂等表或记录作为恢复提交的办法。
