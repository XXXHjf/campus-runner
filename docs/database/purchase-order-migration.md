# 跑腿代买业务数据库迁移

## 目的和约束

`purchase-order-migration.sql` 为跑腿分类增加稳定业务编码和启用状态，并为订单增加业务类型快照与商品金额。顺风车只停止创建新单，不删除分类，也不改变历史订单分类。商品金额不参与服务费计算、不属于平台服务费；代买完成后，商品金额与跑腿报酬会合并转给接单人。

生产数据库为 MySQL 5.5.36；插入默认代买分类和转账额度配置时使用 `SELECT ... FROM DUAL`。该环境执行不带 `FROM` 的常量 `SELECT ... WHERE NOT EXISTS` 会返回 1064 语法错误。

当前商家转账单笔额度为 200 元，因此初始化唯一额度配置 `runner_transfer_single_max` 为 `200.00`。代买订单的用户实付和接单人应收均不得超过该额度；两处共用一个配置，避免额度调整后不一致。接单人只在订单完成后收到一笔合并转账。以后商户额度变化时只需更新这项配置。

## 发布与验证

执行前备份生产数据库，随后执行 SQL。验证分类编码唯一、顺风车 `enabled=0`、代买 `enabled=1`，并确认历史订单数量和状态未改变。部署新版 API 后验证普通跑腿仍可发布、顺风车无法发布、代买金额由服务端重新计算。

## 回滚

紧急回滚优先将 `PURCHASE` 分类的 `enabled` 更新为 `0`，阻止新单。新增字段保持兼容，不在紧急回滚中删除。若必须进行结构回滚，需先确认不存在代买订单；存在代买订单时不可删除 `business_type` 或 `product_amount`，应保留数据并由管理员处理。
