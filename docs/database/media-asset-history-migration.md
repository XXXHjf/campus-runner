# 历史图片迁移审计边界

历史图片迁移器、巡检脚本和旧字段兜底已从当前代码移除，本页不再保留不可执行的 dry-run/apply 命令或旧观察期实施方案。历史实现通过 Git 历史追溯。

当前图片身份以 `tb_media_asset` 的业务绑定为准，接口、用途和授权见 [统一图片资源接口](../api/media-assets.md)；旧列清理与回滚边界见 [旧兼容链路清理](legacy-compatibility-cleanup.md)。

## 仍需保留的证据

历史 `media-asset-history-migration.sql` 仅创建迁移台账，不能替代实际图片迁入，不是当前常规发布步骤。已有 `tb_media_migration_ledger` 数据可保留作审计：`MIGRATED` 表示建立并核验绑定，`SUPERSEDED` 表示已有替代绑定，`DISCARDED` 表示已确认弃用，`FAILED` / `MANUAL_REQUIRED` 表示需核对的失败或人工事项。这些历史状态不等于当前对象仍可访问。

已移除的 PAYMENT_QR 用途及用户收款码绑定不得重新用于新上传。排查旧环境时，先核实实际表结构、有效绑定和 OSS 对象；不能重新部署旧迁移器、伪造绑定或通过清空旧值绕过删列保护。

任何对象清理都须以业务绑定和可恢复证据为依据，不按 OSS 目录批量删除。代码回滚不删除媒体或台账；必须恢复数据时先保留失败现场及迁移后新增业务，按生产手册在隔离库验证并制定恢复范围。
