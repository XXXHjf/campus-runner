# Repository Guidelines

## 项目结构与模块组织
- 入口与全局配置：`app.js`（生命周期与全局方法）、`app.json`（路由/窗口配置）、`app.wxss`（全局样式）。
- 功能页面：`pages/` 下按功能分目录（如 `pages/index`、`pages/orders`、`pages/mine`），每个目录包含 `.js/.wxml/.wxss/.json`。
- 复用模块：通用组件在 `components/`，工具与通用逻辑在 `utils/`，接口与网络调用集中在 `services/`。
- 资源与依赖：静态资源在 `images/`；`miniprogram_npm/` 存放通过 DevTools 构建的三方包；环境/IDE 配置在 `project.config.json` 与 `project.private.config.json`。

## 构建、测试与开发命令
- 安装依赖：`npm install`（保持 `tdesign-miniprogram` 与锁文件一致）。
- 构建 npm：微信开发者工具中执行 **工具 → 构建 npm**，更新 `miniprogram_npm/`。
- 运行/调试：用微信开发者工具打开项目，点击 **编译**；需要真机验证时开启真机调试。
- `package.json` 未定义额外脚本，预览、上传均使用开发者工具面板。

## 编码风格与命名
- 统一 2 空格缩进，文件保持 UTF-8/ASCII。
- JavaScript 使用 CommonJS（`require`）；变量与函数用 `camelCase`，组件名用 `PascalCase`。
- 工具函数尽量保持纯净并放在 `utils/`；网络请求与接口封装集中在 `services/`，避免视图层掺杂请求。
- WXSS 遵循 TDesign 类名（如 `t-` 前缀），自定义样式使用 `kebab-case`。
- 原生 `tabBar` 页面不得通过页面级触摸事件模拟左右切换；除非明确改造为统一的自定义
  导航和 `swiper` 容器，否则页面只允许纵向滚动，通过 `tabBar` 完成主页面切换。
- 横向 `scroll-view` 必须限制在页面视口内，避免使用负边距叠加扩展宽度使根页面产生
  横向溢出；页面根容器应阻止横向位移，同时保留横向滚动区域自身的手势。

## 公共组件与设计系统
- 小程序界面统一以 TDesign、`app.wxss` 中的 `--cr-*` 设计令牌，以及
  `components/ui-*` 公共界面组件为基础。新增或修改页面时，页面壳、内容分区、固定操作栏
  和空状态必须优先复用 `ui-page`、`ui-section`、`ui-action-bar`、`ui-empty-state`。
- 输入、选择、按钮、开关、上传、弹窗、抽屉和提示等交互，TDesign 已提供满足需求的组件
  时不得重新使用原生标签和页面级 WXSS 手工实现。图标必须使用 TDesign 图标或项目正式
  资源，不得使用 Emoji、文本符号或临时绘制图形代替。
- 复用的目的是统一和便于管理，不是强行封装。TDesign 组件配合公共 WXSS、设计令牌
  已能满足的按钮、输入等基础控件，应直接使用，不为转发属性、事件或套样式再包装组件。
  同类样式在第二处出现时优先集中到公共样式；只有存在稳定、实质性的共享结构或交互时
  才抽取公共组件、Behavior 或工具函数。公共界面组件不得直接请求接口、操作全局业务
  状态或写死页面跳转。
- 分类选择、地址选择、订单确认等领域交互只有在模型和流程稳定、且确实被多个业务复用时
  才抽取；一次性字段和单页流程留在页面内，避免为了“公共”制造大而全的高耦合组件。
- 全局公共样式统一使用 `cr-` 前缀；页面样式必须使用页面或功能根前缀限定作用域。不得新增
  `.card`、`.title`、`.button`、`.header`、`.container` 等无作用域通用选择器，也不得通过
  固定超大边距、空白占位、`px/rem` 混用或深层 `!important` 覆盖来凑布局。
- 修改设计令牌或公共组件后，应核对受影响调用代码；新增页面交付前应搜索同类重复实现。
  滚动、安全区、键盘遮挡、弹层、底部操作栏及常见分辨率表现由用户手动验收；涉及上传、
  授权、隐私协议或系统输入能力时，提醒用户补做真机验证，不默认由代理进行高成本自动操作。

## 测试指引
- 遵循根目录 `AGENTS.md` 的“开发检查与人工验收”：开发只做最低必要可用性检查，
  按本次改动选择少量语法、组件注册或关键逻辑检查，不默认跑全量测试。
- 已有轻量 Node 回归测试位于仓库根目录 `tests/mini-program/`，仅在相关行为需要验证
  时选择对应测试；不为低风险样式改动额外搭建复杂测试或自动化工具。
- 微信开发者工具和真机的样式、布局、交互验收由用户手动进行并反馈。自动操作耗费
  较多 token 或效率低下时停止尝试，不反复截图、点击或重试；明确说明未验证的部分。
- 手动验收项按影响范围选择：登录/令牌、页面跳转、网络请求、常见分辨率、控制台告警；
  涉及横向滚动时还需检查斜向拖动不带动根页面，纵向滚动和下拉刷新正常。

## 提交与 PR 规范
- 提交信息简洁、祈使式；历史记录常用简短中文摘要（如“修复…”、“新增…”）。
- PR 需说明目的与范围、实际完成的检查和待人工验收项，列出受影响页面及新增配置项；
  有现成关键 UI 截图/GIF 时可附上，不为补齐截图默认进行高成本自动操作。
- 如有相关 issue/任务请关联，并标明环境变更（新的存储键、接口地址等）。

## 安全与配置提示
- 不要硬编码令牌；使用 `tokenManager` 与 `wx.setStorage` / `wx.getStorage` 管理认证状态。
- API 主机放在 `globalData`，敏感配置写入 `project.private.config.json`，避免提交密钥。
- 跑腿首页轮播图必须通过 `services/bannerService.js` 读取后台配置的通用轮播图和当前
  学校轮播图；不得恢复为写死的 OSS 地址、组件库演示图或其他测试资源。轮播接口失败
  时隐藏轮播区域，不得用测试图片伪装正常数据。
- 调整依赖后务必重新执行 **构建 npm**，确保上线代码与锁文件一致。
